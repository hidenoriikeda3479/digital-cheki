# 10 — 品質・試験・完了判定

根拠：R1各受入条件/NFR、DEC-010/011/017、C08。

## 実装規約
TypeScript strictを維持し、anyや強制アサーションで型不一致を隠さない。外部値はunknownから検証する。
状態を文字表示で判断せずenum/union等で明示し、未定義値はエラーにする。数値/日時/容量単位を契約で統一。
副作用はテスト可能な境界へ隔離。モックの都合で画面の入力検証や本番の認可要件を省かない。
日本語UI・セーフエリア・キーボード・文字拡大・押しやすさを考慮。装飾デザインの完成は別の工程。
コメントは意図/制約を簡潔に。別プロジェクトでの句点/文体ルールを当プロジェクトの確定条件にしない。

## 試験の層
| 層 | 対象 | 証明できないこと |
|---|---|---|
| 単体 | 入力/役割/状態/時計/エラー | 実機カメラやネイティブ保存 |
| 契約 | Mockと将来HTTPの共通入力出力/認可想定 | 実サーバー実装の安全性そのもの |
| 保存結合 | DB・ファイル・復旧 | OSごとの差の網羅 |
| 画面 | 入力/待ち/失敗/経路/利用者切替 | 実転送速度/実通知配信 |
| 実機 | カメラ・描画・保存・終了復旧 | 他OS/他端末/本番設定での成功 |
| 実API結合/公開 | 別端末配布・認可・期限・実通知・署名 | 現段階では未実施 |

mock testではfetch等を許可せず、必要に応じNative依存も封じる。fixtureとclockは試験ごとに分離。
大量のsnapshotだけで状態機械や保存の正しさを代替しない。テスト0件/skip/例外握り潰しを成功にしない。

## 実行コマンドの取り扱い
apps/mobileのscriptsを実読し、以下が存在する場合に実行する。
```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test:ci
```
未設定なら「設定未整備」。初期品質整備の依頼範囲内でのみscriptと必要なテストを追加する。
採用案はJest＋jest-expo。既存基盤やExpo版を確認して導入する。依存変更時はexpo-doctorも確認。
coverage100%を勝手な完了要件にせず、重要不変条件/異常系の具体例を優先する。

## 要求への対応
[要件対応表](../../docs/requirements-coverage.md)の各FRに、実装ファイルとテストIDを実装後に記入する。今は「未確認」のまま。
[受入試験候補](../../docs/testing/acceptance-cases.md)は作るべき試験の一覧であり、実行済み結果ではない。
全P1を最終対象にするが、依頼された機能から順に実装。先行モックで登録・再設定・問い合わせを後回しにすることと対象外にすることを混同しない。

## 完了報告テンプレート
1. 実装した機能とFR/画面ID
2. 主な変更ファイル、設計・仮値の変更
3. 実行コマンドと結果。実行できない理由も記す
4. iPhoneでの操作手順/期待結果。Expo Goか開発ビルドかを記す
5. Android未確認、ネイティブ差、API結合未確認、公開前課題

「API通信を差し替えれば完成」は設計目標。リモート通知/署名/ストア審査/課題確認まで不要とは報告しない。
