# 段階05 フレーム・落書き契約

対象：P1-FRM-001〜003、P1-DRW-001/002、P1-REC-001/002の編集部分。G-007の撮影写真一覧から写真を押してG-008/G-009へ直接進む。原画像は編集キャンバスで表示し、別の写真詳細画面は挟まない。完成JPEG生成は段階06の既存実装へ接続し、送信はG-007の受付単位操作で行う。

`EditingService`はcredential、受付ID、写真IDを入力し、認証済みグループと保存済み採用写真を毎回検証する。`load`は写真単位の保存済み編集状態を返す。画面操作はControllerのメモリ内draftだけを変更し、DEC-037により「完了」で`saveDraft`を呼んで写真ごとのframe、quality、elementsを一括保存する。期待revisionが異なる場合はConflict、役割違いはForbidden、写真なしはNotFound、記録の読書き失敗はStorage。既存の`append`、`undo`、`setFrame`、`setQuality`はサービス内部の互換操作として残るが、画面からは呼ばない。フレーム変更を確定すると、その写真の線・スタンプをdraftから全消去する。キャンセルは変更せず、取り消しでも消去前の要素は戻せない。

SQLiteの既存`KeyValueStore`に、環境/source/グループ別の`photo-edit/<photoId>`をschemaVersion 1で保存する。元画像バイトは入れず`originalRef`、元画像寸法、フレーム、画質、線/スタンプを再現する正規化座標、色、幅、操作順、revision、更新日時を記録する。編集中の複数写真の変更は画面セッション内のメモリで保持し、「完了」で写真ごとに順次保存する。写真をまたぐ単一トランザクションではないため、途中失敗時は未保存分を保持して再押下できる。完了前の強制終了・ログアウトでは、その編集中の変更は復元しない。別アカウントへ切り替わった遅い結果は画面へ表示しない。保存エラーは画面へ表示する。

プレビューはReact Native Skia 2.6.2を使用する。SDK 57のExpo Go同梱版を`expo install`で追加。元画像1枚だけをSkiaへ読み、miniの写真窓へ歪めず中央クロップして要素を描く。表示座標と写真の基準座標は`geometry.ts`で相互変換し、完成画像の描画にもこのモデルを利用する。DEC-033以降の寸法は`cheki-format.ts`のinstax mini外枠54×86 mm・写真部分46×62 mmに集約。白枠の左右各4 mm・上4 mm・下20 mmのうち、上下配分はOPEN-002の実機確認用仮値。8色、太さ3段階、スタンプ相対サイズ11%を維持。画質の実機評価は未確認。白枠の仕上がり・滑らかさを本番保証値にしない。

DEC-036の画面配置：縦スクロールと固定380pxキャンバスを外し、セーフエリア内の編集領域へmini外枠全体が入る最大倍率で写真を表示する。枠なし時は同じ編集座標へ写真を表示する。上部に写真番号と「完了」、下部にペン・スタンプ・フレーム・画質・写真切替・取り消しのアイコンを重ね、選択した操作のパネルだけを写真の上へ表示する。選択肢は別写真の編集状態を変更せず、フレーム変更確認を維持する。ツールバーは完成JPEGへ含めない。

DEC-039の操作補足：G-007の完成画像サムネイルには端末の細線幅で濃い縁を付け、白フレームを画面の白背景から区別する。編集キャンバス上では左右の横移動を写真切替と判定せず、ペン選択時は線として扱う。前後の写真切替は「写真」メニューのボタンで行う。DEC-038のスワイプ判定しきい値は廃止した。切替時のメモリ内draftと「完了」時保存はDEC-037を維持する。

「完了」はdraftを保存してから完成JPEGを作ってグループ端末領域へ確定し、成功してからG-007の撮影写真一覧へ戻す。失敗時は編集画面を維持して再操作可能にする。JPEGだけを編集状態の代わりにしない。

Nodeの実SQLiteファイル再オープン試験で写真別の編集復元、フレーム変更と旧revisionの拒否、画質保存、他グループ/ファン遮断、書込失敗を確認する。画面試験のSkiaはNative描画の代わりに要素を模擬するため、iPhone Expo Goの表示、描き心地、強制終了後のNative読込は別に確認する。業務外部通信はない。本番APIと外部スタンプ取得は未実装。
