# 段階12：端末写真管理・退会・問い合わせ

対象：P1-UPL-008（G-013）、P1-ACC-001/002（F-014）、P1-SUP-001（G-014/F-015）。HTTP URLや本番メールの契約は未作成。

現行DEC-043：G-013は送信確定後の受付だけを表示する。送信前の中断受付はここから準備・確定・送信せず、新しい撮影受付からやり直す。確定後の失敗・結果不明は同じ受付IDで照会/明示再送できる。以下の未確定受付の送信記述は以前の動作。

## 操作の契約

- `LocalPhotoManagementService.list(credential)` はグループ本人の写真、送信状態、端末削除状態、空き容量警告を返す。`deleteUploaded(credential,intakeId,photoId)` は当該グループのアップロード済み写真だけを対象にする。未完了・他グループ・二重操作は拒否する。
- 削除前に撮影台帳を `deleting-local` にし、元画像・縮小画像・同じ写真IDの完成JPEGをファイルラッパーで消し、最後に `locally-deleted` を記録する。中断時は同じボタンで再開する。送信済み台帳、仮サーバーの画像・履歴、ファンが受信した画像には触れない。撮影台帳には写真IDと撮影情報を残す。`deleting-local` は確認対象とし、自動再送や自動写真削除はしない。
- 複数選択時は`deleteUploadedBatch(credential, photos)`で受付と送信状態を受付ごとに照合し、撮影台帳を削除中・削除済みへそれぞれ一括更新する。元画像は写真ごとに消すが、完成画像フォルダーの一覧取得は一度だけ行う。途中失敗なら削除中の記録を残し、同じ選択を手動で再試行する。個別削除の契約は単件のバッチ呼び出しとして維持する。
- 空き容量警告は端末残容量 **200 MiB未満**の仮値で、`local-photo-management.ts` に集約する。業務上の保存上限や自動削除条件ではない。グループ端末の写真の保存期間上限は設けない。
- `AuthService.deleteAccount(credential)` はファン会員の現セッションを確認し、モック認証台帳の状態を `deleted` にして全モックセッションと未使用再設定参照を失効させる。`AuthController.deleteAccount()` がその後に端末の認証情報を消して画面をログアウト状態にする。サーバー履歴や端末ファイルを一括削除しない。モックの受取・QR・アルバム等は認証復元で拒否する。端末外コピーの遠隔削除は保証しない。
- `SupportService.submit(credential,subject,content)` は空白のみの件名・内容を拒否し、認証されたグループ・ファン・ゲストのIDと役割、受付ID・時刻、件名・内容をモック専用台帳へ保存してから受付結果を返す。保存失敗は完了にしない。画面は処理中の二重押下を防ぎ、失敗後は再操作可能。実メール・添付・運営画面はない。
- ログアウト、端末写真削除、退会、開発用モック初期化は別操作。開発用初期化は既存の確認ダイアログとモック名前空間限定の処理を維持する。

G-013の画面は`LocalPhotoManagementService.list`の写真を受付IDでグループ化し、受付表紙を重ねたサムネイルで表示する。複数枚の受付から写真グリッドへ進み、拡大画面では閲覧だけを行う。DEC-057により、確認付きの手動削除は一覧の複数選択から実行する。送信済み✓/未完了×は受付単位の結果を右下へ表示する。削除済み・削除途中のファイルURIは画像として開かず、削除記録と再開操作を残す。

一覧の表示用照会は受付ごとの写真・完成画像・送信状態・撮影相手名を最大4受付ずつ並行して取得する。結果は受付IDを維持して撮影日時順に並べ、待機中は画面中央に進捗表示を重ねる。受付数が多い実機での所要時間は未計測。

更新後の`LocalPhotoManagementService.list`は`ManagedIntake[]`（受付、参加アイドル表示名、受付単位の送信状態、写真列）を返す。`retryUpload(credential,intakeId)`は明示操作1回につき受付1件を扱い、未確定なら完成画像の準備・対象確定後に送信する。結果不明/送信中はまず同IDを照会し、その呼出しで新たに転送しない。送信済みは拒否。端末削除は引き続き受付全体の完了時だけ許可する。画面は削除済み写真を一覧から除外し、削除途中だけ再開用の枠を残す。参加アイドルは受付のID集合、撮影日は写真の端末ローカル日付で検索し、写真の撮影日時で並び替える。個別写真へ送信状態を複製しない。

DEC-032により`ManagedIntake`へ`recipientName`を追加。`IdentificationService.getIntakeRecipientName(credential,intakeId)`はグループ認証と自グループの保存済み受付を確認してから名前を返す。モックでは会員の登録名を認証台帳から取得し、ゲストは「ゲスト」。不明な受付・会員名は明示エラーとし、G-004の番号存在確認にはこの値を使わない。全画面モーダルはセーフエリア内に戻る操作と日時・名前を置き、同じ受付内の写真のみサムネイルで切り替える。本番APIの受付詳細にも同等の認可が必要。
