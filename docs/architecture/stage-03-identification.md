# 段階03 ファン特定と撮影受付の契約

対象：P1-ID-001/002/003、P1-SHT-001。G-003/G-004/G-005、F-006の会員用表示。写真撮影は段階外。

`apps/mobile/src/services/contracts/identification.ts` をMockと将来のHTTPの共通呼出し口とする。全操作は認証credentialを受け、Mockは段階02のセッションを再検証する。QR・番号自体は認証手段ではない。

| 操作 | 入力 | 成功値・表示 |
|---|---|---|
| `getOwnIdentity` | ファンcredential | 当人の会員番号・QR payload。F-006だけで表示 |
| `resolveQr` / `resolveNumber` | グループcredentialと読取値 | `RecipientResolution {recipientRef,kind}` またはnull。グループ画面には該当有無だけを表示し、内部参照は画面文字・ログに出さない |
| `listSelectableIdols` | グループcredential | 自グループの承認済み・選択可能なアイドルID、表示名、あれば肖像ソース。モックは同梱画像を返す |
| `saveIntake` | グループcredential、受取参照1件、重複しないアイドルID 1件以上 | `CaptureIntake {id,groupId,recipientRef,idolIds,acceptedAt}`。再検証・グループ別端末保存の完了後に成功 |
| `getLatestIntake` | グループcredential | そのグループで最後に保存した受付またはnull。別グループの記録は返さない |

空欄・不正形式は`Validation`、未知のQR/番号はnull、無効セッションは`Unauthenticated`等、別役割・他グループのアイドルは`Forbidden`、保存失敗は`Storage`として扱う。QRを二重処理せず、成立後はプレビューを止める。結果不明の保存を成功表示しない。選択途中は画面内のdraftで、`saveIntake`完了後だけ確定受付とする。戻る操作では確定受付を維持し、再起動で再取得する。ログアウト/アカウント切替で前利用者の画面状態を消すが、元グループの保存済み受付は消さない。

モック専用の仮形式：`dc:1:member:<参照>` / `dc:1:guest:<参照>`。会員番号はモック用文字列で、桁数は本番仕様として未確定。ゲスト一時番号は原文どおり6桁文字列で先頭0を保持する。現時点のseedゲストは新規発行ではない。QRのエンコード値は認証トークンでなく検索キーであり、グループ認証と受取人の存在・状態を毎回検証する。OPEN-020/024の期限・卒業時の詳細を確定しない。

仮サーバーの識別catalogは既存fixture・認証レコードと別キーで初回のみseedする。受付は端末SQLiteのグループ別名前空間に保存し、仮サーバーcatalogやファン領域と混ぜない。保存済み受付は上書き削除せず記録列へ追加する。内部参照は次段階の撮影へ引き渡せる不透明IDとする。本番HTTPのURLや全API仕様は今回確定しない。

現行UIでは参加アイドルを写真付き2列グリッドで複数選択する。モック肖像は`assets/mock-idols/`の架空人物をアプリに同梱し、catalog自体や利用者データへ写真バイトを保存しない。肖像が未提供なら「写真なし」を示し、選択権限は従来どおりサービス側で確認する。

受付保存が成功したら、その戻り値の受付IDでG-006の撮影画面を直接開く。保存成功の専用画面は表示しない。保存失敗時は選択画面でエラーを示し、撮影画面の読み込み失敗時は保存済みの同じ受付IDで再試行する。再試行で受付を重複作成しない。
