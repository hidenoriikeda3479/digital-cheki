# 段階07 仮アップロード契約（実装前整理）

## DEC-029による現在の送信境界

DEC-040の操作境界：G-007の送信・再送ボタンは完成画像、受取人、参加アイドル、枚数の確認ダイアログを開く。キャンセルでは`confirmIntake`も`send`も呼ばない。「送信する／再送する」で現在の受付IDと写真集合を再確認し、対象確定の成功後に受付単位の転送を始める。独立した送信状況画面は追加しない。

DEC-059：入口はG-007見出し右上の＋に隣接した送信アイコンとする。確認ダイアログは「送信先」に認可付きで取得した会員名（ゲストは「ゲスト」）、「アイドル」に受付で選択したアイドル名を表示する。入口の移動と文言変更で、キャンセル・確定・再送の処理順は変えない。

DEC-060：確認後の送信結果が受付全体で`uploaded`のときだけ撮影画面を閉じ、識別状態を初期化してG-003 QR読取を開く。撮影済みのローカル画像・送信履歴は維持する。`failed`・`unknown`・確定/照会エラー時はG-007に留まり、手動再送または結果照会を可能にする。送信成功だけを示す画面は設けない。

現在のアプリ配線は`contracts/batch-upload.ts`、`services/mock/mock-batch-upload.ts`、`features/upload/batch-upload-controller.ts`を使用する。`send(credential, intakeId)`は受付の確定済み完成画像集合を一括操作として受け、グループ領域へは受付単位の`status`と`failureCount`だけを永続化する。`observe`は照会だけで転送を開始せず、失敗後は`send`の手動操作のみ。結果不明は`query`で照会してから再送を判断する。仮サーバーの写真ID別受領記録は受取認可・重複防止・写真ごとの7日期限に必要であり、グループ側の写真別送信状態ではない。転送は複数ファイルの順次コピーで、受付全体をファイルとDBの単一原子トランザクションとは扱わない。部分成功時は受付全体を失敗と表示し、手動再送時に既受領IDを飛ばす。旧`mock-upload-service.ts`と`upload-screen.tsx`は現行組み立てから外れている。R1の写真別状態/3回失敗UIとの差はDEC-029とOPEN-029で管理する。

対象：P1-UPL-001〜007、P1-REC-001/002の転送状態、P1-NTF-001の通知生成条件。G-011/G-012をG-010へ接続する。実API/S3/Pushは未実装。

`UploadService.observe(credential, intakeId)`は確定済みの写真集合を取得し、写真IDごとの状態・試行失敗回数・進捗・完了日時・期限・仮サーバー保管状態を返す。`start(credential, intakeId, photoId, onProgress)`だけが転送を開始する。`query`は同一写真IDの仮サーバー記録を照会し、画像バイトを再送しない。`PhotoTransferPort`が完成JPEGの端末内URIから仮サーバー名前空間へのコピーを担当し、S3直接転送/API中継の選択をUIへ持ち込まない。0枚・未確定・別グループは拒否する。

現行UIではG-007の確認ダイアログで「送信する」を押した後、受付の確定済み写真の未送信分を順に送る。G-011/G-012の独立画面は現行導線へ接続せず、受付単位の失敗後再送・結果不明の照会を手動操作に限る。確認ダイアログを再表示しただけでは転送しない。

グループ領域の転送台帳は`unsent/transferring/failed/needs-attention/uploaded`と内部的な`unknown`を保存する。`unknown`は完了応答喪失・再起動時の結果不明であり失敗回数を増やさない。失敗回数はサーバー保存前の確定した失敗を1試行につき1回だけ加算する。取消は今回は提供せず、ログアウトしても元グループの処理を継続し別画面へ結果を反映しない。このカウント案はOPEN-019の仮方針であり本番確定ではない。3回で要対応にするが、次の手動操作を禁止しない。

モックの仮サーバー領域は写真IDを一意キーとして完了記録と画像を保持する。画像コピーと記録を別段階とし、FileSystemのFileHandleで256KiBごとにコピーしてバイト進捗を通知する。コピー済み・記録前の失敗は再試行時に同じIDのファイルを検査して再利用する。記録済みならコピーを拒否し、照会で完了を復元する。進捗100%はコピー完了であり、記録成功までは`uploaded`にしない。完了日時は仮サーバー記録時、期限はその168時間後のUTC ISO時刻。再照会・再試行では延長しない。

期限処理はモック起動・操作・テスト時計変更時に実行する。`now >= expiresAt`で取得を拒否し、仮サーバー画像を削除できれば`deleted`、削除失敗中は`expired`とする。画像が消えても`uploadedAt`とアップロード済み事実を保持し、再送しない。アプリ終了中に独立ジョブが動くとは扱わない。元写真・完成JPEGは期限処理で消さない。

通知レコードは固定済み撮影単位の全写真が仮サーバーで完了し、かつ全て`now < expiresAt`で画像が存在するときだけ1回記録する。部分失敗・先行写真の期限切れでは作らない。OPEN-017に対し期限延長・成功集合の縮小・部分通知はしない。通知一覧/Push配信は段階09以降。

仮サーバーの保存失敗、実コピー失敗、完了応答喪失、時計変更、遅延・連続失敗などは開発用の制御で再現する。本番bundleへモック制御を含めない。HTTP/OpenAPIのURLやS3転送方式は未確定のため、今回はTypeScript契約だけを記録する。
