# 会員700001向けの追加チェキ

ユーザー指定：9月から週3程度・土日多め、白フレームと落書き付きのアイドル/ファン2ショット。最新5件を未受信、それ以前を受信済みにする。

## 追加データ

- 対象：既存モックの会員700001（fan-a / recipient-member-a、fan@example.test）。ID・パスワード・会員名は変更しない。
- 2026/09/02〜2026/10/14の19撮影日・26受付・26枚。12日分が土日。平日は月〜金へ分散（9/02水、9/10木、9/18金、9/22火、9/28月、10/08木、10/14水）。8名の既存架空アイドルを割り当てる。
- 9/12は5枚、9/27は4枚。他の日は各1枚。追加7件には既存の生成素材を再利用し、別の写真ID・受付IDで保存する。新しい画像生成は行っていない。
- 未受信：10/04、10/08、10/10、10/11、10/14の5件。残り21件は実際のファン専用ファイルと受信記録を作る。すでに利用者が受信したものを未受信へ戻さない。
- 素材：`apps/mobile/assets/mock-cheki/cheki-01.jpg`〜`cheki-19.jpg`。生成方式・プロンプト・フレーム寸法は同フォルダーREADME。

撮影日時と仮アップロード完了日時は分ける。撮影日は過去の日付、アップロード完了は今回の追加実行時。取得期限は既存仕様どおりアップロード完了から7日。10/04の写真も新規追加直後は取得できる。既存の期限を延長したり、期限判定を無効化したりしない。

## 配線と保存

開発モックのアプリ組み立てでのみ`demoChekiPhoto`を注入。APIモードやproductionへは追加しない。生成画像はExpo Assetで同梱素材からローカルへ読み出す（開発中はMetroからの素材取得）。業務API・S3・外部画像サイトは呼ばない。Expo Goに既に含まれるexpo-asset 57.0.18を直接依存として明記した。

`seed-demo-cheki.ts`は安定ID・写真ごとの完了マーカー・全体マーカーを保存する。仮サーバーへコピーし、21枚はファン領域へ別ファイルとして受信中→ファイル確定→受信完了の順で記録する。通常再起動では再投入しない。利用者による受信・削除・お気に入りを巻き戻さず、既存の別写真も削除しない。既に旧サンプル写真や撮影データがあれば26件に加えて残る。

v2追加移行ではv1の写真別マーカーを再利用し、既存19枚のIDを維持して撮影日時だけを訂正する。グループ・受付・受取人が一致するデモ写真に限定し、アップロード日時・期限・画像・受信台帳には変更を加えない。追加7件だけをコピーし、途中中断時は完了済みを再コピーしない。全体v2マーカー確定後の再起動では更新処理を行わない。ID内に旧撮影日が残る場合があるが、表示や日付集計にはcapturedAtを使用する。

仮通知へ参加アイドルを記録し、写真の撮影日を用いる人気急上昇集計にも接続。グループ端末に撮影元が存在したという履歴を捏造せず、仮サーバーへのデモインポートとして扱う。

## 実機確認

Expo Goを再読み込みして初回追加を待つ。会員700001のfan@example.testでログインし、カレンダーの平日が分散し、9/12に5枚、9/27に4枚あることを確認。未操作の状態ではアルバムに21件、ホームの未受信に最新5件、一括受信後は26件となる。既存データ・受信や削除の操作がある場合は件数が異なる。再起動で重複しないこと、削除した写真が復活しないことを確認する。

iPhone実機の操作・表示は未確認。本番へのデータ投入ではない。
