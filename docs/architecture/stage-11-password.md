# 段階11：パスワード変更・再設定の契約と仮運用

対象は P1-AUTH-002、P1-FAN-004 の変更部分。ログイン中のグループ・ファンは `changePassword(credential,currentPassword,newPassword)`、ログイン画面からは `requestReset(email)` → モック受信箱で参照確認 → `completeReset(requestId,reference,newPassword)` を使う。いずれも成功後は新パスワードでログインし、旧パスワードを拒否する。ゲストにはパスワードを作らない。

入力エラーは `Validation`、旧パスワード・参照の誤りは `Unauthenticated`、削除済み・停止済みは `Forbidden`、使用済みは `Conflict`、期限切れは `Expired`、永続化失敗は `Storage`。再設定参照は申請IDと対象アカウントIDへ紐づけ、別の申請との組合せを拒否する。メール配送は行わず、`MockPasswordInbox` は開発用モックだけへ置く。

再設定参照はモック専用の不透明な文字列、有効期限10分、同じアカウントで再申請すると旧参照を無効化する仮運用。形式と期限は本番仕様として未決。メール・パスワード・参照をログへ出さない。モック仮サーバーの既存認証台帳内でパスワードのソルトとダイジェストを更新し、参照を使用済みにする。既存デモアカウントは初回変更後に固定デモパスワードの特別扱いを終了する。本番のパスワード保管方式ではない。

変更・再設定後に既存の別端末セッションを失効するかは OPEN-003 の本番JWT設計待ち。現モックでは既存セッションは各自のログアウトまたは既存のモック期限まで残る。この挙動を本番保証として画面に表示しない。

G-001/F-004は共通ログイン画面として表示し、どちらのメールアドレスも同じ内部フロー `reset` から再設定する。元の `reset-group` / `reset-fan` は共通化で廃止した。原文の P1-AUTH-002 に G-002 が記載される一方、G-002 はホーム・未完了復旧として維持する。画面IDの正式な整理は OPEN-015 のまま。ログイン中のファンは F-014 のパスワード変更部分へ対応する。これらは Expo Router の新規ルートではなく画面内の状態である。

DEC-045により、ログイン中のグループはG-002ホームの「設定」からパスワード変更へ進む。完了・戻る操作は設定画面へ戻す。共通ログイン画面の再設定導線とOPEN-015は変更しない。

DEC-069により、内部契約の`reference`は維持しつつ画面では「再設定コード」と表示する。現在のモックでは再設定申請後に画面内の表示操作で取得でき、実メール送信はない。6桁の会員登録認証コードとは別の一時文字列であり、本番の再設定形式は未決。
