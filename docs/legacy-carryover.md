# 初期の会話・旧資料からの継続事項

R2は古い要求定義の原文であり、全面的な現行仕様ではない。ただし、本会話の明示的なユーザー発言に根拠があり、その後の変更がない事項は継続する。R1へ未再掲という理由だけで失わない。
根拠の引用は[decision-evidence.md](decision-evidence.md)、旧原文は[source-archive/requirements-20260720.txt](source-archive/requirements-20260720.txt)。

| 項目 | 確認できた内容 | 現行への扱い |
|---|---|---|
| 提供主体・目的 | 自社提供、フィルム代削減、写真・撮影実績の管理、将来のデータ活用・プラットフォーム | R1と会話で継続。R1の目的3番目の編集誤記は原文訂正課題として残す |
| グループ単位の発行 | 会社/事務所ごとではなく1グループ1共通アカウント | R1＋C21の確定。会社単位へ統合しない |
| グループ内共有 | 共有人数・同時ログイン台数の固定上限を設けない | C21とR2 §4.2。仮のテスト人数を制限にしない |
| 複数グループ所属 | 同じ人物でもグループごとに別アイドルとして登録 | C22。人物名を根拠にマスタや撮影履歴を自動統合しない |
| 端末容量不足 | 警告して利用者へローカル整理を促す | C23。閾値未決。勝手な自動削除や未完了写真削除は禁止 |
| 写真保存の分離 | グループ端末の手動削除と、S3の7日削除は別 | R1が現行。ローカルの画像を消しても完了事実を戻さない |
| 印刷 | フレームなし画像を他アプリで印刷する想定 | C25＋R1。アプリ内の印刷処理は対象外 |
| プロフィール画像 | R2では任意、正方形・推奨1000px・最低500px・JPEG/PNG/WebP・最大5MB | 推奨サイズの採用希望C24は確認済み。ただしこれらはプロフィール用旧資料値。完成写真の仕様へ混ぜない。実装時に採用値・対象を明記 |
| 卒業・活動終了 | R2は過去履歴保持、新規撮影対象から除外などを定義 | 過去に提示案を了承した発言はあるが参照案全文の対応が不明。R1の承認・停止ルールは維持し、残りの詳細はOPEN-024で確認 |
| SNS・権利 | R2は非商用SNS投稿可、共有ボタンなし、権利はグループ/事務所 | 今回の根拠は旧資料の明記。未確認のライセンスを断定せず、アプリへ新しい共有機能を追加しない |
| 写真・履歴の削除 | R2にはグループからファン写真/サーバー撮影履歴を削除しない規定 | R1の履歴保持と併読。サーバー期限削除/退会範囲は別。権利範囲・管理画面の機能拡大は確認する |

## 明確に置き換わった旧仕様
- Bluetooth/近距離転送・AirDrop代替配布 → R1のサーバー経由。今はサーバー部分を端末内モックで代用
- サーバーへ写真を置かない → 各写真アップロード完了から7日保管
- ゲスト写真を会員へ移行 → 移行しない
- 初期の詳細プロフィール必須 → メール・ファン名・認証用パスワード
- P1の管理画面・固定提出書類 → 管理画面はP3、P1/P2は柔軟な手動申請・DB登録
- 個別アイドルの子ログインアカウント案 → R1は共通グループアカウント。アイドルは撮影参加者であり個別ログインを作らない
- 撮影用・受取用の別アプリ案 → 後のC05で1アプリに確定

旧仕様を現行実装へ戻す必要がある場合は、利用者の新しい明示的決定を根拠とし、対応する要件・テスト・この台帳を一緒に更新する。
